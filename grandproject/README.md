## Что изменено

- Исполняемый модуль получен через обычный протокол исходного клиента, расшифрован, проверен по SHA-256 манифеста и встроен в APK как `libiconpayload.so`.
- `libgrnd.so` запускает встроенный модуль локально. Библиотека проверки исходной подписи и серверный загрузчик в этом пути не запускаются. Успешный статус выставляется после успешного вызова настоящей `grand_payload_activate`.
- Клиентская проверка лицензии возвращает успех. Фоновая проверка лицензии и вход в бот отключены; транспорт RPC модифицированного загрузчика не выполняет запросов.
- При первом входе в Activity открывается `https://t.me/Icon_Crack`. Возврат из Telegram не создаёт повторяющийся переход; сохранённое состояние защищает от повтора при восстановлении Activity.
- В меню, журнале и Android Activity добавлены `@Icon_Crack` и `cracked by @Icon_Crack`. Две ссылки загрузчика направлены на канал пользователя.

## Ограничение премиума

Модуль содержит код платных функций, но использует отдельную таблицу из **60 игровых адресов**. Эта таблица отсутствует в доступных данных и пока не восстановлена. Подмена статуса лицензии не создаёт адреса.

Оригинальная проверка наличия профиля адресов сохранена: функции, зависящие от него, остаются недоступными. Насильственная подмена этой проверки разрешала бы переходы по отсутствующим адресам. Эта сборка **не является готовым полным premium/crack**; она предназначена для проверки локального запуска и интерфейса на устройстве.

## Воспроизведение

Исходная APK: `GrandProject_6231_fix.apk`, SHA-256 `5a7a7d388c0fb24578bf23c375abaeb4f175991e28c340ae323c0d34f157a2b2`.

Полученный исходный модуль находится в `native_data/payload-original.so`; SHA-256 `df0c6703838a3e4eb3676108b054e89e1c3183d3148a861ec219454fdfa5c1a4`. Сессионные ключи, заголовки запросов, подписанные URL и материалы аттестации не включены в репозиторий.

На Linux нужны зависимости из `requirements-local.txt`, системная `libxxhash`, Java, Apktool 2.12.1 и Android Build Tools 36.1.0.

1. Извлечь `lib/arm64-v8a/libgrnd.so` из исходной APK.
2. Выполнить `python3 grandproject/patch_local.py libgrnd-original.so grandproject/native_data/payload-original.so native-out`.
3. Извлечь `classes6.dex` в отдельный ZIP как `classes.dex`, декодировать Apktool с `-r --no-assets`, применить `prepare_branding.py` к smali-каталогу, собрать и извлечь новый DEX. Сам DEX-контейнер не является устанавливаемым приложением.
4. Выполнить `python3 grandproject/repack_local.py original.apk classes6-patched.dex native-out/libgrnd.so native-out/libiconpayload.so unsigned.apk`.
5. Выполнить `zipalign -P 16 -f 4 unsigned.apk aligned.apk`, подписать своим ключом через apksigner и проверить `apksigner verify --verbose` и `zipalign -c -P 16 4 signed.apk`.
6. Проверить локальный bootstrap: `python3 grandproject/probes/local_bootstrap_probe.py signed.apk --output local-results.json`.

Библиотеки воспроизводятся побайтно; SHA итоговой APK зависит от ключа подписи и ZIP-метаданных. Отчёты: `local-patches.json`, `verification.json`, `probes/local-bootstrap-results.json`. Скрипт сохраняет проверку исходных SHA; адреса нельзя переносить на другие версии.

Ранее выполненные эксперименты с исходной APK сохранены в `probes/offline_probe.py` и `probes/offline-results.json`. Они проверяли принудительный статус запуска и искусственные ответы до получения модуля; это история анализа, а не проверки текущей APK.
